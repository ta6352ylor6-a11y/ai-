# 方案 B：OpenNebula + 财务系统

## 它是什么

OpenNebula 是开源的云管理平台，底层用 KVM。架构比 CloudStack 简单：一台"前端"（主控）加若干台 KVM 母鸡，前端通过 SSH 管理母鸡。前端自带 Sunstone 网页界面（管理员和用户都能用）、命令行和 API。

- 官网：https://opennebula.io
- 官方文档：https://docs.opennebula.io （当前是 7.x 系列）

## 授权（先看清楚）

OpenNebula 分两个版本：

- **社区版（Community Edition）**：Apache 2.0 开源，免费。每 6 个月发布一次新版本，官方不出维护版本，只出修复严重问题的补丁；支持靠社区论坛
- **企业版（Enterprise Edition）**：源码同样是 Apache 2.0，但二进制安装包和企业工具要按商业订阅协议使用，需要付费订阅。比社区版多：额外的错误修复、升级维护工具、技术支持，以及一些"企业集成"（其中就包括官方的 WHMCS 计费模块）

测试和小规模运营可以用社区版。具体版本差异以官网说明为准。

## 财务系统怎么选（调研结果）

OpenNebula 本身有"费用统计（Showback）"功能：可以在虚拟机模板里给 CPU、内存、硬盘设置每小时价格，用量数据能导出成 XML、JSON、CSV。但它**没有注册、充值、下单、支付这些功能**，还是要配财务系统。网上服务商常用的有：

1. **HostBill（商业，推荐对接最省事）**
   - 2025 年 9 月推出了官方 OpenNebula 模块，OpenNebula 官方博客也介绍过
   - 支持卖固定配置的 VPS、灵活的云主机，也支持按量计费：流量、资源用量、系统模板、额外 IP、备份和存储都能计费
   - 支持自动开通、暂停、恢复、删除、升降级
   - 费用：一次性买断授权，网上资料显示约 $599 起，之后每年约 $125 的更新费，部分模块要另外付费。官方没有公开价格，以向 HostBill 询价为准
   - 网址：https://hostbillapp.com/feature/opennebula/
2. **WHMCS + 官方模块**：OpenNebula 官方有 WHMCS 模块（管理租户、配额，支持按用量计费），但**只给企业版用户**。WHMCS 本身也是按月付费的商业软件
3. **第三方 WHMCS 插件**：比如 WHMCS 市场上的 NoCloud OpenNebula 插件，但最后更新在 2021 年，不建议
4. **开源财务系统（Paymenter、FOSSBilling、Blesta 等）**：没找到现成的 OpenNebula 对接，要自己开发对接模块

**建议：**
- 想省开发、愿意一次性花几百美元：HostBill
- 想零授权费：Paymenter（或你选的其他开源财务系统）+ 让 AI 开发 OpenNebula 对接扩展，预计 1 到 2 周

## 整体结构

```
客户 → 财务系统（HostBill，或 Paymenter + 自研扩展）
           ↓ OpenNebula API
       OpenNebula 前端（主控）：核心服务 + Sunstone 界面 + 数据库
           ↓ SSH
       母鸡 1、母鸡 2……（KVM 节点）
```

## 准备什么

- 前端（主控）：推荐 4 核 8G、100GB 以上；系统用官方支持的版本（如 Ubuntu 22.04 / 24.04），全新安装
- 母鸡：物理独立服务器，CPU 已开启虚拟化，系统和前端一致；有一段给 VPS 用的 IP
- 财务服务器：单独一台（HostBill 或 Paymenter），不要和前端装在一起

## 部署步骤

具体命令以你选的 OpenNebula 版本官方文档为准。下面是流程和关键点。

### 第 1 步：选安装方式

官方提供三种：
- **miniONE**：一个安装脚本，最快把整套 OpenNebula 跑起来，官方定位是评估、测试和开发环境。**测试阶段推荐用这个**
- **OneDeploy**：官方推荐的多节点生产环境部署工具
- **手动安装**：用系统软件包一步步装，最灵活

测试阶段让 AI 用 miniONE 先跑起来；确定要正式用时，再用 OneDeploy 或手动方式重新部署。

### 第 2 步：安装前端

1. 添加 OpenNebula 官方软件源（`downloads.opennebula.io` 上对应版本和系统的仓库）
2. 安装前端软件包（核心服务、Sunstone 界面、命令行工具）
3. 启动服务，设置管理员（oneadmin）密码

怎么验证：浏览器能打开 Sunstone 界面并登录（端口以官方文档为准）；命令行执行 `onehost list`、`onevm list` 没有报错。

### 第 3 步：添加母鸡（后续步骤，有母鸡后做）

1. 母鸡装和前端相同的系统，检查 CPU 虚拟化：`egrep -c '(vmx|svm)' /proc/cpuinfo` 大于 0
2. 在母鸡上安装 OpenNebula 的 KVM 节点软件包（会装好 KVM、QEMU、libvirt，具体包名见官方 KVM 节点文档）
3. 让前端的 `oneadmin` 用户能免密码 SSH 到母鸡（官方文档有步骤）
4. 配置网桥，客户 VPS 通过它上网。租的独服先问清楚额外 IP 是路由方式还是要绑定 MAC
5. 在前端添加主机：Sunstone 界面里添加，或用命令 `onehost create 母鸡IP -i kvm -v kvm`
6. 怎么验证：`onehost list` 里母鸡状态是 on

母鸡不需要开发，只是安装和配置。

### 第 4 步：配置网络、镜像和模板

1. 创建虚拟网络：把给 VPS 用的公网 IP 段录进去（地址范围、网关、DNS），绑定到母鸡的网桥
2. 从 OpenNebula 官方应用市场（Marketplace）导入系统镜像：Ubuntu、Debian、AlmaLinux 等
3. 创建虚拟机模板：CPU、内存、硬盘、网络、系统镜像；可以顺便设置每小时价格（Showback）
4. 设置用户组和配额：限制每个客户能用多少 CPU、内存、硬盘、IP
5. 手动开一台测试 VPS，确认能联网、能 SSH 登录、Sunstone 里能打开 VNC

### 第 5 步：连接财务系统

**用 HostBill：** 按 HostBill 的 OpenNebula 模块说明添加 OpenNebula 服务器（填前端 API 地址和账号），建商品，选择模板和网络。

**用 Paymenter 等开源财务系统：** 让 AI 开发对接扩展：
- 参照财务系统现有的服务器扩展结构
- 功能：下单后用模板创建虚拟机、开关机、重启、重装、删除、到期暂停、VNC 链接
- 在 OpenNebula 里给财务系统单独建一个账号，权限尽量小
- 开发前先让 AI 出方案，确认后再写

### 第 6 步：流量额度和超额限速

OpenNebula 能统计每台虚拟机的网络流量。"月流量用完自动限速、每月重置"需要：
- 用 HostBill：先看它的流量计费能否满足（它支持按流量计费）；限速部分可能仍需要一个小程序
- 自己实现：让 AI 写一个定时程序，读取每台 VPS 本月流量，超额后通过 API 修改网卡限速（或调用母鸡的限速设置），每月 1 日恢复

### 第 7 步：完整测试

注册 → 充值 → 下单 → 自动开通 → 开关机、重装、VNC → 到期暂停和删除 → 流量超额限速。

## 常见问题

- Sunstone 打不开：检查服务状态和防火墙端口（端口以所装版本文档为准）
- 母鸡添加后状态是 error：多半是前端 SSH 不到母鸡，或母鸡上 libvirt 没运行
- VPS 没网：检查网桥、虚拟网络配置和商家的 MAC 绑定要求

## 优缺点

- 优点：社区版开源免费；架构比 CloudStack 简单，好装好维护；有成熟的商业计费对接（HostBill）
- 缺点：社区版更新慢，没有官方维护版本；官方 WHMCS 模块只给企业版；用开源财务系统要自己开发对接；界面是"云控制台"风格，普通 VPS 客户用起来偏复杂
